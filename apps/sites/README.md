# Trio · 만화 번역 작업실

데스크톱 중심의 만화 번역·식자 편집 작업실입니다. React 19 / TypeScript / Vinext로 구현했으며 Sites에 비공개로 배포합니다.

## 실행과 확인

```sh
npm install
npm run dev
npx tsc --noEmit
node --test checks/*.test.mjs
npm run build
```

## 동작하는 기능

- 왼쪽 패널 상단의 프로젝트·기록 메뉴, 프로젝트 생성·검색·전환·이름 변경, 프로젝트별 로컬/온라인 처리 모드
- 처리 엔진 설정에서 원본 언어·번역 언어 선택
- 왼쪽 패널 하단에 고정된 `페이지 추가`에서 클릭·파일 드롭으로 JPG/PNG/WebP/GIF와 ZIP 입력, 혼합 선택·실제 압축 해제·한글 파일명·자연수 페이지 정렬
- OCR 영역·원문·신뢰도 표시, OCR 결과 JSON 가져오기
- 이미지 위 더블클릭 편집, 위치 이동·영역 크기 조절, 되돌리기·다시 실행
- 글꼴·크기·굵기·정렬·색상·줄 간격, 흰색 배경 채우기, 페이지 전체 스타일 적용
- 원본/식자/나란히 비교, 줌·화면 맞춤
- 이미지 바깥 좌우 여백 클릭으로 이전·다음 페이지 이동, hover/키보드 포커스 화살표
- 화면 높이 전체를 쓰는 중앙 캔버스, 좌우 패널로 나눈 프로젝트·처리·편집 도구
- 패널 가장자리의 같은 핸들로 접기·펼치기, 좌우 대칭 위치와 360ms의 슬라이드·페이드 전환
- 왼쪽 패널 안의 높이 26px 미리보기 전환·OCR 표시와 한 줄 편집 도구, 페이지 이동·줌 컨트롤
- 사용자가 직접 실행하는 글자 크기 맞춤, 페이지별 엔진 처리 상태·오류와 프로젝트 기록
- 원본 해상도 PNG, 페이지 ZIP, 이미지와 편집 데이터를 포함하는 TRIO 프로젝트 백업·가져오기
- IndexedDB 자동 저장. 저장 실패 시 표시. 브라우저 간 자동 동기화 기능은 제공하지 않습니다.

## 실제 AI 처리 범위

기본 OCR/번역/인페인팅 서버나 API 키는 포함하지 않습니다. 샘플은 편집 체험용으로 준비된 원문·번역문·이미지이며 실제 엔진 처리와 구별합니다. 샘플은 캔버스 편집에 사용하며, 엔진 연결 버튼은 설정을 엽니다. 자동 품질 검사나 검수 완료 판정은 제공하지 않습니다.

업로드한 파일은 브라우저에 저장합니다. 처리 모드 변경이나 업로드만으로 외부 엔진에 전송하지 않습니다. 사용자가 명시적으로 처리를 실행하면 선택한 엔진으로 파일을 전송합니다. 브라우저가 엔진을 직접 호출하므로 배포 서버의 localhost를 사용자 PC로 해석하지 않습니다. HTTPS 작업실의 로컬 엔진 연결에는 브라우저의 로컬 네트워크 접근과 엔진 CORS 설정이 필요할 수 있습니다.

## 엔진 브리지 계약

기존 FastAPI 엔진의 실제 API를 확인하여 `lib/studio-engine.ts`를 맞추거나 아래 계약을 제공하는 브리지를 추가하세요. 이 계약이 기존 Windows 엔진과 이미 일치한다고 가정하지 않습니다.

1. `GET {base}/health`: `{ "status": "ok" }` 또는 `healthy`.
2. `POST {base}/jobs`: multipart `file`, `source_language`, `target_language`. 응답 `{ "id": "job-id" }`.
3. `GET {base}/jobs/{id}`: 상태는 `queued`, `processing`, `running`, `completed`, `failed`, `cancelled`. 실제 단계 이름은 선택적인 `stage` 문자열에 전달합니다. 실패에는 `error`를 포함할 수 있습니다.

완료 응답 예:

```json
{
  "status": "completed",
  "stage": "식자 완료",
  "result": {
    "clean_image": "data:image/png;base64,...",
    "blocks": [
      {
        "id": "region-001",
        "source": "原文",
        "text": "번역문\n다음 줄",
        "x": 10, "y": 20, "w": 25, "h": 15,
        "font": "sans", "size": 32, "weight": 600,
        "align": "center", "color": "#202020", "lineHeight": 1.4,
        "confidence": 0.98, "fill": false
      }
    ]
  }
}
```

좌표는 이미지 전체에 대한 0~100 백분율, 글자 크기는 원본 이미지의 px입니다. `clean_image`는 선택적인 원문 제거 배경이며 PNG/JPEG/WebP data URL만 허용합니다. 원본 이미지와 크기를 일치시켜 주세요. `clean_image`를 생략하면 원본 위에 식자하며 자동 인페인팅이 수행된 것처럼 표시하지 않습니다. 원본 픽셀의 검출 좌표는 엔진에서 백분율로 변환합니다.

OCR JSON 가져오기는 `{ "blocks": [...] }` 또는 영역 배열을 같은 계약으로 받습니다. 중복 ID·잘못된 좌표를 거부합니다. 유효한 작업 결과만 반영하고 실패 시 이전 성공 결과와 편집값을 유지합니다. 수신한 결과는 바로 편집할 수 있습니다. 내용의 정확성은 사용자가 원본과 결과를 직접 보고 판단합니다.

작업 ID와 연결 주소를 보관하여 새로고침 뒤 처리 버튼으로 상태 조회를 재개합니다. `조회 중지`는 브라우저의 조회만 중지하며 원격 작업의 취소를 주장하지 않습니다. 확정적인 엔진 실패는 다음 실행에서 새 작업을 만들며, 네트워크 실패는 보관한 ID로 재조회합니다.

## 사람이 캔버스에서 확인하는 흐름

자동 검수 탭·누락/겹침/넘침 경고·검수 개수·검수 완료 버튼은 제거했습니다. 원본/미리보기/비교를 전환해 사용자가 직접 만화를 보고 번역문을 수정합니다. 글자 크기 맞춤은 사용자가 선택한 영역에서만 실행하는 편집 도구이며 대사를 다시 쓰지 않습니다.

페이지 목록은 처리 대기·처리 중·조회 중지·편집 가능·처리 오류만 표시합니다. `전체 처리`는 기존 검수 표시와 관계없이 모든 페이지를 대상으로 합니다. 처리 오류와 저장 실패, 원격 작업 ID 재개 보호는 유지합니다. PNG/ZIP 내보내기는 품질 판정으로 막지 않으며 ZIP에는 페이지 목록을 담습니다.

기존 v1 데이터의 `reviewed`와 `review/completed` 값은 파일·저장 호환성을 위해 보존합니다. 현재 UI는 `lib/studio-presentation.ts`에서 내용 품질과 무관한 처리 상태를 표시하며, 예전 검수 플래그가 처리 범위나 다운로드를 결정하지 않습니다.

## 주요 파일

- `components/studio.tsx`: 작업실 UI와 작업 흐름
- `lib/studio-model.ts`: 프로젝트·페이지·영역 모델, 이전 데이터 호환·입력 정규화
- `lib/studio-presentation.ts`: 내용 품질과 분리된 페이지 처리 상태
- `lib/studio-storage.ts`: 브라우저 저장
- `lib/studio-files.ts`: ZIP 입력, 이미지 합성, 파일 내보내기
- `lib/studio-engine.ts`: 실제 엔진 연결 경계
- `checks/studio.test.mjs`: 파일·이전 버전 호환·영역 ID·작업 재조회에 대한 회귀 검사

샘플 이미지 자산은 기존 Trio 시안의 자산을 재사용했습니다. 기존 배포 사이트와 로컬 Windows 엔진은 수정하지 않았습니다.

## 상태 전이와 회귀 검사

전체 상태 목록과 이벤트 계약, 저장 호환 정책은 `docs/state-machines.md`에 있습니다. 상태 관찰을 위한 안정적인 DOM 식별자와 aria 상태를 제공하며, 읽기 전용 관찰이 권한이나 실제 처리 성공을 대신하지 않습니다.

```sh
node --test checks/*.test.mjs
```

`lib/studio-state.ts`는 문서/이력/작업/페이지/연결 전이, `lib/studio-persistence.ts`는 단일 쓰기 큐, `hooks/use-studio-persistence.ts`는 복원·저장·충돌 복구 UI의 연결 경계입니다. v1 로컬 기록은 보존하며 다른 탭의 선행 저장은 덮어쓰지 않습니다. 충돌 시 수정한 프로젝트를 각각 TRIO로 백업한 후 새로고침할 수 있습니다.
