# Trio 상태 경계 후속 점검

**목표** 기존 화면과 v1 프로젝트를 보존하면서 남아 있는 충돌 경계를 재현하고 수정한다.

**설계** 기존 reducer와 저장 큐를 확장한다. 전체 상태 관리 교체와 새 의존성 도입은 하지 않는다. 단축키는 포커스·모달·작업 상태로 판정하는 순수 함수로 분리하고, 내보내기 가능 여부는 화면과 실행 경로가 같은 판정을 사용한다.

**대안과 결정** 전체 UI를 하나의 대형 상태 머신으로 합치면 검증 범위가 불필요하게 커진다. 기존 23개 상태 목록을 갱신하고, 실제 재현한 저장 충돌·단축키·백업·내보내기 경계만 명시화한다. 사용자 요청에 따라 기존 배치와 기능은 유지한다.

## 보존 조건

- 기존 IndexedDB 이름·키와 `trio-studio-v1` 파일 형식을 유지한다.
- 저장 충돌은 자동으로 재시도하거나 덮어쓰지 않는다. 편집 내용과 프로젝트 백업은 보존한다.
- OCR의 1,000개 영역 제한은 유지하되 직접 만든 프로젝트 백업은 1,000개를 넘는 영역도 복원한다.
- PNG와 ZIP은 같은 페이지 상태 기준을 사용한다. 보류·실패 페이지는 먼저 조회 재개 또는 이전 결과 편집을 선택한다. TRIO 백업은 항상 별도 복구 경로로 남긴다.
- 모달과 일반 입력창의 키보드 소유권을 보존한다. IME와 브라우저의 수정키 조합을 가로채지 않는다.
- 실제 엔진의 응답을 꾸미거나 인증·공유 범위를 변경하지 않는다.

## 검증 초점

- 다른 탭 저장 충돌 후 추가 편집은 경고를 지우거나 다른 탭을 덮어쓰지 않아야 한다.
- 설정·이름 변경·다운로드창에서 Ctrl+S는 다른 모달로 전환하지 않아야 한다.
- Ctrl/Alt+T·O·방향키는 캔버스 명령을 실행하지 않아야 한다.
- 선택한 페이지가 없거나 조회 중인 상태에서도 TRIO 백업은 가능해야 한다.
- 편집 가능한 페이지가 없어도 실행 중인 다른 프로젝트의 조회 중지는 가능해야 한다.
