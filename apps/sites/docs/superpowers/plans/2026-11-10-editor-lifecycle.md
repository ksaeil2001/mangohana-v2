# Trio 편집 수명과 기록 후속 점검

기준 소스 `5fa3179`, 배포 v14. 기존 상태 흐름 26개와 64개 검사를 유지하며 이번에 재현한 경계만 수정한다. 저장 스키마·화면 배치·인증·엔진 API는 유지한다.

## 설계와 결정

- 문서의 undo/redo와 실제 발생한 처리 기록은 수명이 다르다. 과거 문서 스냅샷을 적용할 때 현재 기록을 보존하고, UI의 실제 undo/redo는 시간과 ID를 이벤트에 담아 기록한다. 시간 생성은 reducer 밖에서 한다.
- 텍스트 세션과 좌표 체크포인트는 실제 차이가 있을 때만 undo에 들어간다. 원문으로 되돌린 세션과 사라진 영역의 늦은 이벤트는 redo를 지우지 않는다. undo/redo 진입 때 편집과 제스처를 먼저 정리한다.
- 엔진 작업 ID는 복원 시와 수신 시 동일한 규칙으로 검증한다. 원본 이미지의 실패 응답은 업로드하지 않는다. 빈 OCR 영역 ID는 새 고유 ID를 부여해 대사를 보존한다.
- 프로젝트 생성 초안과 이름 변경 초안은 별도로 보관한다. 이름 변경 취소가 새 프로젝트 이름에 영향을 주지 않는다.
- 전체 상태 모델을 교체하는 방법은 현재 순수 전이와 기존 검증을 불필요하게 흔들어 사용하지 않는다. 기존 모듈을 확장하고 AX에 undo/redo 가능 횟수를 노출한다.

## 실행과 검증

- [x] 기존 64개 검사 통과, 새 경계 검사 10개 중 8개 실패 재현.
- [x] 브라우저에서 생성 초안 → 이름 변경 입력 → 취소 → 생성 초안 오염 재현.
- [x] 문서 이력과 처리 기록 분리, 빈/늦은 영역 체크포인트 무시.
- [x] 엔진 작업 ID·원본 이미지·빈 영역 ID 경계 보강.
- [x] 편집 세션 종료와 독립된 모달 초안 연결, undo/redo 관찰값 추가.
- [x] 전체 회귀 검사, TypeScript, 브라우저의 no-op 편집·기록 보존·초안 분리 확인.
- [x] 독립 검토와 배포용 빌드, 상태 목록과 검증 한계 갱신.
- [x] 기존 Site에 같은 접근 범위로 반영할 소스 준비. 배포 완료는 Sites 버전 기록으로 확인한다.

검증 결과: 76개 검사·TypeScript·배포 빌드 통과. 실제 PNG 다운로드 후 undo/redo에서도 기록 보존, no-op 편집의 redo 유지, 모달 초안 분리를 브라우저에서 확인했다. 추가 검토의 드래그 메타데이터/편집 기준값 지적은 실패 검사로 재현한 뒤 수정했다.
