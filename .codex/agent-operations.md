# MangoHana V2 에이전트 운영

03단계에서 정의한 지속 운영 정책이다. 기존 20단계 로드맵과 감사 A~I의 정확성·보안·데이터 보호·검증 요구를 유지한다. 에이전트 설정은 제품 OCR·번역·LaMa 모델 변경 권한이나 다음 단계 실행 권한을 부여하지 않는다.

## 모델과 설정 범위

| 역할 | 모델 | 추론 | 호출 조건 |
|---|---|---|---|
| main | GPT-6.1 Sol (`gpt-6.1-sol`) | 기존 세션/사용자 설정 보존 | 계획·제품 코드 수정·통합·최종 판단 |
| 기본 하위 | GPT-6 Luna (`gpt-6-luna`) | medium | 아래 위임 조건을 만족하는 좁은 분석/검증 |
| bug_triage | GPT-6 Luna | medium | 원인 불명 로그·최초 데이터 오류·최소 재현 |
| test_verifier | GPT-6 Luna | low | 독립 검증이 필요한 복잡한 변경의 테스트·회귀 |
| quality_reviewer | GPT-6.1 Sol | medium | 실제 이미지·OCR·번역·식자의 독립 품질 비교 |
| critical_reviewer | GPT-6 Astra (`gpt-6-astra`) | low | 아래 Astra 예외 조건 |

기본값은 `.codex/config.toml`, 네 역할은 `.codex/agents/<역할>.toml`이다. 현재 전역 main은 Sol/max이며 이를 이 정책에서 변경하지 않는다. 하위 에이전트의 낮은 기본 추론은 메인의 추론을 낮추지 않는다.

프로젝트가 신뢰되고 작업 cwd가 저장소 내부일 때 프로젝트 설정을 읽는다. 부모 `C:/dev/Projects`에서 열린 채팅이 하위 `.codex`를 읽는다고 가정하지 않는다. 명시 실행 옵션 > 프로젝트(가까운 경로 우선) > 선택 프로필 > 사용자 > 관리 기본값/시스템 > 내장 기본값 순이며 관리 요구사항은 별도 제약이다.

`config/read`의 프로젝트 layer와 `disabledReason`으로 실제 로딩을 확인한다. 이 설치 버전에서 일회성 `-c projects.<경로>.trust_level` 지정만으로 미신뢰 layer가 활성화된다고 가정하지 않는다. 신뢰는 프로젝트가 스스로 부여하지 않으며 전역 설정은 현재 사용자가 허용한 범위에서만 변경한다. 설정을 작성한 뒤 기존 채팅의 핫리로드를 가정하지 말고 저장소를 작업 폴더로 연 새 세션에서 확인한다.

하위 설정은 먼저 명시 spawn 값 > `[agents]` 기본값 > 부모 값 순으로 결정된다. 그 뒤 선택된 custom agent 파일의 명시 model/effort가 각각 우선한다. 따라서 역할에는 둘 다 지정했다. 모델만 지정하고 추론을 생략하지 않는다.

현재 도구 스키마를 먼저 확인한다. 역할 선택 인자가 제공되면 실제 지원 인자로 역할을 선택한다. 인자가 없으면 존재하지 않는 `agent_type` 등을 보내지 않는다. 대신 메인만 해당 역할 파일의 지침을 읽어 필요한 내용과 정확한 model/effort를 명시하고 최소 컨텍스트로 위임하며, native 역할 파일의 자동 적용은 미검증으로 기록한다. 모델 ID/추론이 사용 불가능하면 대체 모델로 우회하지 않고 차단 사유를 보고한다.

전체 대화 복제는 지양한다. `fork_turns`를 지원하는 현재 V2 도구에서 모델/추론을 명시할 때는 `none`으로 새 컨텍스트를 사용한다. 전체 이력 fork의 모델 override 가능 여부는 실제 도구 지침을 따르며 오래된 스킬 예제를 우선하지 않는다.

## 메인이 직접 처리할 일

단순 파일 조회, 간단한 코드 수정, 명확한 컴파일 오류, 확정적 테스트 집계, 기존 로그로 원인이 명확한 오류, 기존 함수 사용법 확인, 동일 근거가 충분한 작업은 메인 단독으로 처리한다. 작업이 길거나 분리 가능하다는 이유만으로 서브에이전트를 자동 생성하지 않는다.

위임은 독립 조사를 병렬 수행할 실익, 원인 분석용 별도 컨텍스트, 구현 후 중요한 독립 품질 검토, 중대한 위험에 대한 제삼자 검증 중 하나가 있을 때만 한다. 메인이 목적과 완료 조건을 정한 뒤 필요한 최소 역할을 선택한다. 제품 코드 수정과 통합은 메인 Sol이 맡는다.

## 호출·반복·종료 제한

1. 메인을 제외하고 전체 작업 트리에 동시에 최대 2개만 실행한다. 설정 상한은 동시 열린 하위 스레드 수를 제어하며 총 호출 수·토큰·주간 사용량 상한은 아니다.
2. 한 호출에 질문 하나와 완료 조건 하나를 전달한다. 관련 파일·함수·로그·페이지/영역 ID·기존 결론만 전달하고 불필요한 비밀/전체 대화/원본 자료는 보내지 않는다.
3. 모든 호출 전 목적·선택 모델/추론·역할·질문·입력 범위·완료/중단 조건·누적 호출 수를 남긴다. 다른 에이전트가 이미 끝낸 조사를 되풀이하지 않는다.
4. 기본은 같은 질문/역할 1회다. Luna/Sol의 후속은 관련 소스 변경·새 실패 로그 등 새 증거가 있을 때만 1회 허용한다. 그 뒤에도 실패하면 범위를 닫고 차단 사유·부족한 증거를 보고한다. 무한 재시도·전 저장소 재검토·역할 순환을 하지 않는다.
5. 모든 하위 역할은 분석/검증만 수행한다. 제품 코드·테스트·설정·사용자 데이터 수정과 하위의 추가 생성/재위임을 금지한다. 필요한 검사 산출물은 메인이 지정한 격리 감사/임시 경로에만 쓴다.
6. 검사가 통과하고 관련 코드·설정·환경이 유지되면 같은 검사를 반복하지 않는다. 실패·skip·NOT RUN·증거 부재는 성공으로 바꾸지 않으며 사용량을 이유로 성공 조건을 낮추지 않는다.
7. 완료한 에이전트는 결과를 한 번 받고 재호출하지 않는다. 새 근거 없는 확인 인사·동일 질문·빈 follow-up을 보내지 않는다. 결과/증거 경로를 재사용한다.
8. 완료 슬롯 정리는 실제 도구 기능을 따른다. V2의 자동 회수를 이용하고 존재하지 않는 close 도구를 만들지 않는다. V1에서 close가 지원될 때만 종료한다. 대기 이벤트를 이용하고 잦은 상태 폴링을 하지 않는다.
9. 판단이 충돌하면 같은 원본·소스 revision·로그를 비교한다. 다수결·상위 모델이라는 이유만으로 정답을 확정하지 않는다. 미해결은 미해결로 둔다.

## Astra 예외 조건

다음 중 하나가 입증된 경우에만 `critical_reviewer`를 선택한다.

- 같은 원인의 P0가 근거 있는 수정 2회 후에도 남음. 두 diff·재현 입력·실행 결과를 전달한다.
- 중대한 데이터 손실 또는 보안·권한·사용자 소유권 위험이 확인됨.
- 일반적인 원인 분석으로 해결하기 어려운 구조적 아키텍처/동시성/상태 관리 문제가 있음.

문제당 원칙적으로 1회, low부터 시작한다. 실패 증거·관련 소스·해결할 질문을 좁히고 일반 후속 검토에는 투입하지 않는다. 추가 호출이나 더 높은 추론은 새 증거·필요성·범위·중단 기준을 먼저 보고하고 현재 사용자 승인 범위 안에서 메인 Sol이 판단한다. 서브에이전트는 스스로 승격하지 않는다.

## 검증 기준과 보고

원본·사용자 수정/확정 용어·소유권·보안·권한·비밀·기존 산출물을 보존한다. AI 검토를 사람 검수로 쓰지 않는다. 합성 테스트·규칙 QA 100점·이미지 밖 픽셀 보존을 실제 의미 정확도·마스크 내부 작화·전체 제품 성공으로 승격하지 않는다. 정답/실행 증거가 없으면 확인 불가/null+사유를 기록한다.

각 역할은 TOML의 출력 계약을 따르고 끝에 실제 모델·추론(확인 불가는 미확인), 하위 수, 완료/차단 상태를 쓴다. 메인 최종 보고에는 사용 모델별 역할과 생성한 하위 에이전트 수를 명시한다. 호출 목적·입력 범위·명령·로그/파일·재현·확실성·미검증·다음 최소 조치를 기존 단계 기록에 남긴다. 새 범용 진행 원장을 만들 필요는 없다.

토큰·비용·주간 사용량·절약률은 측정된 값만 기록한다. 미측정은 null/미측정이고, 주간 계정 합계·개별 작업 소비·제품 로컬 추론비는 구분한다. 동시 2개 제한을 비용 예산으로 표시하지 않는다. 이번 설정은 Goal 시작/예산/정지 정책을 바꾸지 않는다.

## 단계별 적용

| 단계 | 구성 |
|---|---|
| 04~08 계약·평가기 | 메인 Sol, 필요시 Luna test_verifier |
| 09 OCR 누락 | 필요시 Luna bug_triage → 메인 구현 → 필요한 Luna test_verifier |
| 10 이미지 마스크 | 메인 Sol + Sol quality_reviewer |
| 11 번역 의미 | 메인 Sol + Sol quality_reviewer |
| 11M 모델 A/B | 별도 실험 승인·고정 입력/정답/자원 게이트 후 메인 Sol + Sol 품질; 심각한 설계 문제만 Astra |
| 12 식자 | 메인 Sol + 필요한 테스트 검증 |
| 13~14 복구·메모리 | 메인 Sol + 필요한 Luna 원인/테스트 |
| 15~18 통합·출시 | 메인 Sol 중심; 중요한 위험이 있을 때만 추가 검토 |

표는 후속 단계의 운영 계획이다. 각 단계는 별도로 요청된 범위만 실행하고 03단계 종료 후 자동 진행하지 않는다.
