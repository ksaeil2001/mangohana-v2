# MangoHana V2 일본어 글줄 전수 추출과 한국어 번역 품질 개발 계획

2026-11-20 KST · 제품 개선 설계 · 기준 버전 `01292d903b2c7a85b4eb7145c6c49555434da14f`와 현재 작업 폴더의 Linux 0B 하네스. 아래 확인칸은 앞으로 수행할 작업이다.

**목표**는 처음 보는 원고에서 대사와 그림 속 글자를 모두 추적하고, 전문가가 수정 없이 쓸 수 있는 한국어 페이지 비율을 높이는 것이다. 자동 처리가 놓친 글과 검수로 넘긴 쪽도 평가에 포함한다.

## 순서와 작업 범위

아래의 1–7번은 Windows 안내에 맞춘 검토 번호다. 실제 착수는 **3번의 글줄 병합 오류**부터 시작한다. 이후 순서와 6번의 조건부 착수 기준은 [2026-11-21 실행 우선순위](#실행-우선순위와-착수-조건)를 따른다.

- **승인 범위와 기준선.** 첫 제품 수정 전에 현재 소스·설정·미커밋 0B 파일의 지문과 필요한 코드 사본을 보관한다. 비교 실행은 어떤 바이트를 사용했는지 재현할 수 있어야 한다. 기존 원고·모델 지문·검증 결과·사용자 편집값·원본 Electron 저장소는 보존 대상이다.
- **0B 한 장.** 창작 원고 한 장에 CPU 4개 분량·RAM 6 GiB·스왑 0·PID 256, 시작 시 Windows 7,168 MiB·WSL 6,912 MiB, OCR·Qwen·LaMa 단계별 최대 1회 조건을 적용한다. 1,536은 0B의 Qwen 입력과 생성 토큰 합계 상한이다. 적재·계산·출력·파이프라인 연결을 따로 판정한다. OOM·메모리 할당 실패·자식 정리 미확인은 남은 호출을 중단하고 저장된 기록으로 확인한다. 호환성 오류와 비정상 출력은 각 사유로 남긴다. 기존 실제 실행 기록은 `BLOCKED`이고 6 GiB에서 Qwen 계산 성공은 미검증이다. 실모델 시험, 새 다운로드·설치, 추가 호출은 각 승인 범위에서만 시행한다. [0B 범위와 마지막 관측](../../validation/2026-11-20-v2-headless-linux-0b.md)
- **작화와 원문.** 제안 기본값은 대사·내레이션은 근거 있는 위치에 식자하고, 효과음과 그림 위 간판은 원문과 한국어 뜻을 조회할 수 있게 하면서 원화를 보호하는 것이다. 작품에서 명시한 처리 의사가 우선한다. 자동 판독, 사용자 확정문, 번역, 원본 픽셀을 각각 복원할 수 있어야 한다.
- **버전과 복구.** 아래 기능은 서버의 제품 프로필로 선택한다. 기능을 추가하는 단계에서 `productOnnx().configuration`에 실행 코드·알고리즘 설정을 포함하고, Linux에서 불러오는 모듈은 `inputs.py`의 `SOURCE_FILES`에 넣는다. Canvas를 바꾸기 전 기존 렌더러 바이트와 SHA-256을 보관한다. 새 렌더러는 격리한 제품 빌드에 별도 지문을 부여한다. 0B 기준선은 보관한 고정 번들과 당시 설정으로 재현한다. 실패 시 기존 프로필과 마지막 검증본을 열 수 있어야 한다. [제품 빌드](../../../packages/ai-engine/build.mjs) · [0B 입력·렌더러 지문](../../../scripts/v2/linux-0b/inputs.py)

## 1. 기준표와 실패 원인부터 측정한다

**담당 코드**는 기존 `packages/evaluation/annotation-v1.schema.json`, `dataset-contract.mjs`, `offline/ocr.mjs`와 신규 `packages/evaluation/offline/text-coverage.mjs`다. Stage02 평가기의 IoU 0.5 영역 대응과 NFKC 문자 오류 계산을 재사용한다. Stage05에는 이미 글줄 좌표·전사 상태·읽기 순서·후리가나 부모·효과음 처리 의사·합침과 분할 기록이 있다. [사람 정답 형식](../../../packages/evaluation/annotation-v1.schema.json) · [기존 OCR 평가기](../../../apps/desktop/scripts/evaluate-automation-quality.mjs)

- [ ] 독립 검수자가 모델 출력을 보기 전에 원본 전체를 표시한다. 대사·독백·내레이션·밖의 대사·효과음·후리가나·미상은 기존 역할을 쓴다. 간판·화면·필기처럼 기존 역할과 겹치는 특성은 `annotationSha256 + lineId`에 묶인 보조 태그로 기록한다. 일부만 읽히는 원문은 읽힌 구간, 판독 불가 사유, 좌표를 보존한다. 전문가 번역 참고본은 같은 페이지와 사용 권리가 확인된 평가 자료로 관리한다.
- [ ] 신규 `summarizeTextCoverage({annotation, inventory, comparison, stage02Page})`는 `byRole, missingLineIds, duplicateLineIds, completeReadablePage`를 반환한다. 사람이 원본만 보고 확정한 정답과, 후보 공개 후 작성한 대응표를 분리해 두 지문을 실제 출력에 묶는다. `missingRegionIds`와 `extraRegionIds`가 있는 기존 영역 지표를 보존한다. 줄이 합쳐지거나 쪼개진 사례는 원래 줄 ID와 문자 구간이 대응할 때만 반영한다. 대응을 확인할 수 없으면 사유와 함께 미측정으로 남긴다.
- [ ] 고정 예제로 **정답 10줄 중 효과음 1줄을 두 검출기가 함께 놓치면 검출 9/10, 무누락 추출 페이지 0/1**을 확인한다. 빈 판독, 오탐, 중복, 잘못된 순서, 사람이 확인한 무문자 페이지도 각각 넣는다. 미검수 원고의 품질값은 `null`과 사유다. 현재 `evaluateOcrPages`는 `dev/calibration`용이다. 봉인된 최종평가는 7의 Stage16 관측에 연결한다.
- [ ] 실제 개발 자료에서는 **사람이 자른 원본 → 판독기**, **사람이 전사하고 순서를 정한 일본어 → 번역기**, **원본 페이지 → 제품 전체**를 같은 페이지에서 비교한다. 각 실행은 비용·권한을 따로 잡는다. 세 결과로 영역 탐색, 글자 판독, 문맥 번역, 식자 연결 중 우선 고칠 곳을 정한다.

**완료 증거**는 원고·정답·출력 지문, 고정 집계의 손계산 일치, 노출 작품과 독립 작품의 분리다. 필수 정답이 없는 동안 측정 도구와 합성 결과까지만 완료로 기록한다.

## 2. 판독 실패가 있어도 읽은 줄을 웹과 CLI에서 열 수 있게 한다

**연결 지점**은 Python `recognize`의 응답 → `product-onnx.cjs` → 제품 `engine.cjs` → `apps/engine/store.mjs`·`server.mjs` → Sites·기본 CLI다. 신규 `packages/ai-engine/quality/text-inventory.cjs`에 `buildTextInventory(data, binding)`와 저장 검증을 둔다.

- [ ] `ocr.py`가 현재 NFC 정규화·공백 제거 뒤의 `source`만 내보내므로, 새 응답은 그 직전의 `rawSource`도 저장한다. 정규화 이미지와 응답의 결속을 확인하고, 엄격한 `extractionFromOnnx` 호출 **전에** `text-inventory.json`을 만든다. 버전, 작업·시도·페이지 ID, 업로드 원본 및 정규화 PNG의 각 SHA-256, 정규화 프레임 크기, OCR 설정 지문을 담는다. 줄마다 `lineId`, 원래 검출 ID들, 정규화 프레임의 픽셀 좌표, 원시 판독·정규화문, 판독 상태, 소속 영역, 중복·포함 관계를 둔다. 검출 점수는 위치에 관한 값이다. 판독 불가 줄·글을 못 찾은 말풍선·미탐색 영역도 보인다. 구버전에 관측 전 원문이 없으면 `rawSource=null`이다.
- [ ] 모델 실행 실패나 응답 유실에는 관측된 사실만 기록한다. 정상 응답으로 만든 목록은 임시 파일 검증과 원자적 게시 후 작업 상태에 지문을 연결한다. 체크포인트 재사용 시 `onnx-ocr.json`과 목록을 재검증한다. 구버전은 확인 가능한 원시 파일에서 파생하거나 ‘기록 없음’을 반환한다. 저장 실패·취소·늦게 도착한 예전 시도의 결과가 마지막 정상 목록이나 사용자 수정값을 덮지 못해야 한다.
- [ ] 신규 소유자 전용 `GET /jobs/{id}/text-inventory`를 저장소 검증, Sites 프록시 허용 목록, `studio-batch-engine.ts`·`studio.tsx`, `web-review-batch.mjs`에 연결한다. 상태 조회에는 건수·가용 여부만 싣고 상세는 요청할 때 읽는다. 화면과 CLI에는 원문·좌표·사유를 반환한다. 서버 파일 경로는 내부 작업 디렉터리에서 결정한다. 빈 줄이 있는 합성 6줄은 **읽힌 5줄과 보류 1줄 조회, 완성 PNG 0개, 번역·LaMa 호출 0회**여야 한다. 기존 `/result`는 검증된 후보 전용이다. 다른 소유자 조회·작업 재개·체크포인트 변조도 시험한다. ## 3. 작은 글자와 타일 경계 누락을 줄인다

**변경 위치**는 `scripts/v2/local_review/text_detector.py`, `ocr.py`의 `crosscheck_text/recognize`, `pages.py`의 `select_regions`다. 고정된 PP-OCRv4 세션을 사용하고 계산 횟수를 검출 뷰, OCR 작업, Baberu 판독으로 나눠 관측한다.

- [ ] `iter_text_tiles(width, height, side, overlap)`로 전체 정규화 프레임을 덮는다. 첫 개발 후보는 긴 변이 1,536px를 넘을 때 **최대 1,536px 타일, 192px 겹침, 한 번에 한 타일**이다. 마지막 타일은 끝 좌표에 붙이고 같은 시작점을 제거한다. 축소한 전체 보기와 원본 해상도 보기를 구분한다. 모서리 좌표를 페이지 픽셀로 되돌리고 내부 타일 경계에서 잘린 글은 이웃 타일의 온전한 관측과 합친다.
- [ ] 원시 관측을 먼저 남기고 동일한 글줄만 병합한다. 겹친 두 상자의 크기만으로 본문 옆 루비나 별도 세로줄을 지우지 않는다. 독립 글줄 지지 영역, 방향, 같은 원본 획의 대응이 모호하면 두 후보의 관계를 남긴다. Baberu는 고유 crop을 한 번 읽는다. 경계가 잘린 후보에는 원본에서 여백을 넓힌 crop, 회전 근거가 있는 후보에는 방향을 바로잡은 crop 중 하나를 골라 예산 내에서 비교한다. crop 지문·변환·원시 판독·실제 횟수를 남긴다. 두 판독이 충돌하면 미확정으로 두고 추정 철자로 원문을 덮지 않는다.
- [ ] 2×2 타일 예제에서 기존 두 전체 검출이 함께 놓친 작은 간판이 1회 추출되고, 경계 글줄은 1회, 본문·루비는 각각 남아야 한다. 타일 예산이 3/4에서 끝나면 미탐색 영역을 표시한다. 종류별 누락·오탐, Baberu 호출 수, 시간·최고 RAM을 기준선과 짝비교해 적용 범위를 정한다. 저해상도·흐린 원본의 해결되지 않은 줄은 검수 상태다. [기존 타일·빈 말풍선 시험](../../../tests/v2/test_local_review_coverage.py)

- [ ] 채택 기준과 허용 품질 차이·최소 개선폭·검수 시간·자원 한도는 **개발 표본으로 정하고 최종 결과를 열기 전에 고정**한다. 높을수록 좋은 평가축에서 `차이 = 제품 − 전문가`, 허용 저하폭을 `δ ≥ 0`으로 정의한다. 의미와 자연스러움 각각의 작품 단위 짝비교 신뢰구간 하한이 `−δ` 이상이고, 중대 오류·무수정 사용·편집 시간 기준도 충족해야 도달로 판정한다. 정답·평가자·표본이 부족하면 해당 주장은 미검증으로 남는다. 운영 worker를 실제 서버에 연결해 업로드부터 재열기까지 통과해야 공개 웹 경로의 결과를 주장할 수 있다.

### 실행 우선순위와 착수 조건

1. **3번의 글줄 병합 오류부터 수정한다.** 모델을 적재하기 전 단계에서 분리 글줄이 합쳐지는 현상을 재현했다. 기존 Python 회귀 하나로 전후 차이를 확인할 수 있다.
2. **1번 최소 집계와 2번의 글줄 ID·좌표 연결을 준비한다.** 10줄 집계와 원본에 연결된 글줄 값을 고정해, 다음 변경마다 누락이나 잘못된 대사 연결을 바로 잡아낼 수 있게 한다.
3. **4번의 컷 순서·말풍선 연결과 작화 보호, 이어 5번의 번역·식자를 개선한다.** 고정 OCR, 번역 응답, 복원 이미지로 잘못된 순서·불필요한 마스크·잘림을 먼저 검사한다. 순서와 대사 연결이 확인된 같은 원문으로 문맥 보강 전후를 비교한다.
4. **2번의 작업실·CLI 재조회와 3번의 고해상도 탐색을 이어 간다.** 읽힌 줄·보류 줄을 실제 제품 경로에서 검증한다. 더 넓은 탐색은 평가할 작은 글자가 있는 개발 원고와 자원 여유가 확보될 때, 기존판과 같은 원고의 전후 수치를 보고 추가한다.
5. **6번은 단일 요청 한계나 재작업 사례가 잡힌 때 처리한다.** 사례 확인 전에는 해당 기록을 모으면서 다음 준비를 진행한다. **7번의 표본·판정표 준비는 첫 작업과 함께 시작**하고, 실평가는 아래 조건을 갖춘 뒤 실행한다.

### 첫 자동 이미지의 무보정 합격률과 전후 보고

- **분모**는 사람이 원본을 보고 사전에 식자 대상으로 확정한 독립 평가 페이지 전체다. 두 판에 같은 페이지 수 `N`을 쓴다. 실패·보류·미실행은 합격 분자에서 빠지며 분모에 남는다. 무문자 쪽과 주석 전용 쪽은 각각 원화 보존과 필요한 결과를 집계한다.
- **분자**에는 첫 자동 출력 그대로 **글줄·읽기 순서, 번역 의미, 원문 제거·작화 보존, 한국어 식자 가독성**을 사람 검수에서 모두 통과한 쪽만 넣는다. 재실행 이미지와 사람이 고친 결과는 원본·첫 자동 결과와 지문을 따로 보관한다. [기존 품질 정책](../../../packages/evaluation/policy/stage08-v1.1.json)
- **전후 표기**는 `기존판 합격 장수/N (합격률) → 개선판 합격 장수/N (합격률), 차이 +x%p`다. 차이는 `100 × (개선판 합격 장수 − 기존판 합격 장수) / N`이다. 예를 들어 **집계 검증용 합성 20장**에서 기존판이 합격 12·보류 4·실패 3·미실행 1, 개선판이 합격 14·보류 3·실패 2·미실행 1이면 **12/20 (60%) → 14/20 (70%), +10%p**다.
- **함께 볼 수치**는 누락·오독·오탐·중복·순서 오류, 화자·호칭·부정·수량의 중대 오역과 빈 번역, 잔상·작화 손상·잘림·가독성 결함의 건수와 영향을 받은 페이지 수다. 버전별 실제 확인 범위를 함께 표기한다. 수정 시간은 첫 결과를 사람이 고치기 시작해 사용할 수 있게 될 때까지의 실제 작업 시간을 페이지별로 기록한다. 무수정 합격은 수정 0분이며, 시간 기록이 없으면 미측정이다. 같은 쪽을 잰 표본의 중앙값(분/장)과 측정 장수/예정 장수를 두 판에 함께 제시한다.
- **초기 개선 목표안은 기준선 대비 +10%p**다. 개발 표본에서 기준선과 남은 개선 여지, 예정 표본의 작품 수·페이지 수를 확인해 달성·판정 가능한 최종 개선폭과 허용 결함·수정 시간 범위를 정한다. 독립 평가 결과를 열기 전에 표본, 기준, 합격 판정 방법과 함께 고정한다. 비교 시 같은 쪽의 합격·불합격 전환과 작품별 결과도 기록한다. 현재 실제 전후 합격률·결함 변화·수정 시간은 **미검증**이다.

### 7번 제품 배치의 첫 결과를 판정표에 연결

변경은 로컬 첫 이미지 검수 도구, 해당 회귀와 계획·검증 기록에 한정한다. 두 격리 저장소에서 같은 합성 원고를 대조한다. 최초 보류 뒤 재시도에 성공한 경우, 변조된 PNG, 수동으로 고친 이미지, 실행이나 정리가 미확정인 경우를 대조한다. 첫 접수 자료의 지문, 내보낸 평가 파일, 판정표 준비까지 같은 입력으로 확인한다.
