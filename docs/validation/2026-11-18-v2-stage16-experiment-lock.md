## 잠금이 발행되는 조건

공개 진입점은 `createExperimentLock(input, savedPreregistrationSha256, currentExposure)`이다. 호출자는 미리 보관한 사전등록 SHA와 현재 11M 선정 기록·홀드아웃 사용 이력의 SHA 두 개를 전달한다. 같은 요청 안에서 변경된 입력을 다시 해시해 신뢰할 기준으로 삼으면 최신성이나 사전 고정 시점을 보증할 수 없다. 이 모듈은 공급한 기록의 일치 여부를 검사한다. 실제 기록의 발행자·권리·미열람 여부는 별도 증거가 필요하다. [구현](../../packages/evaluation/stage16-experiment-lock.mjs) · [합성 입력 형식](../../tests/v2/fixtures/stage16-experiment.mjs)

| 대조 대상 | 확인한 동작 |
|---|---|
| 후보 선정과 개발 노출 | 11M 선정 기록은 근거 SHA와 작품·누출 그룹·문맥을 갖춰야 한다. 미실시는 근거 SHA가 있고 선정 항목이 비어 있을 때만 받아들인다. 작품·그룹·문맥 가운데 하나만 겹쳐도 차단한다. 같은 그룹의 미배정 페이지에 개발 노출 이력이 불명인 경우도 차단한다. |
| 분할·표본·정답 | Stage05로 작품 단위 분할, 권리 메타데이터, 기준 파일 바이트와 동결 기록을 검증한다. 등록한 각 표본에 대응하는 S16-01 네 조건을 다시 계산해 작품·페이지·원본·봉인한 정답·조건표 SHA를 대조한다. 한 표본이 어긋나면 전체 잠금 ID가 `null`이다. |
| 사전 기준과 한도 | Stage08의 사전등록 14개 항목을 사용한다. 주 지표·최소 효과, 비열등성 한계, 자원·비용 상한과 중단 규칙을 고정한다. 기존 등록 SHA 아래에서 기준·폰트·모델·표본을 교체할 수 없다. 합성 입력의 비용 상한은 실측 비용과 별개다. |
| 결과 열람 후 튜닝 | 원래 동결 기록과 이력을 보존하고 해당 작품·누출 그룹의 페이지를 `holdout → dev`로 기록한다. 이력에는 이전·현재 SHA가 남으며 해당 표본을 대체해야 다시 잠글 수 있다. 튜닝 이력의 끝을 잘라 예전 등록을 재제출해도 현재 이력 SHA와 달라 차단한다. 새 독립 표본의 잠금에서도 기존 강등 기록을 확인할 수 있다. |

강등 결과는 오프라인 평가에 적용할 분할 기록이다. 원본 manifest·정답 파일·이미지를 이동하거나 덮어쓸 필요가 없다. 합성 입력에서 잠금이 성립해도 Stage05의 정답 미열람 상태에서 확인한 사람 정답 수는 0이며, Stage06의 최종 홀드아웃 평가 진입점은 계속 차단된다. 이 두 조건을 공개 함수로 검사했다. [집중 테스트](../../tests/v2/stage16-experiment-lock.test.mjs)
