## 실행과 저장

| 경계 | 동작과 확인한 내용 |
|---|---|
| 예약 | 명시적 실행 요청에 owner, 작품·페이지, generation과 세 revision, 원본·입력·부모 지문, 요청 키와 실행 ID, provider·모델·버전·profile, 실행 계보와 승인 ID를 결속한다. 소유 경계가 공급하는 현재 승인과 요청 전체 해시를 확인한다. 승인 만료, 바뀐 owner·mode·입력, 잘못된 부모에는 호출이 없다. |
| 동시성 | 기존 `atomicState`로 새 상태를 고유 임시 디렉터리에 기록·동기화하고, 로컬 파일시스템의 배타적 하드 링크로 같은 세대의 작성자 한 명만 확정한다. 예약, 시작 의사, 실제 시작 근거, 취소, 관측, 게시 영수증은 이 순번이 있는 저장소에서 관리한다. 같은 요청의 재제출은 조회로 끝나고, 다른 payload나 이미 소비한 슬롯은 거부한다. 시간 기반 잠금 회수가 소비 이력을 바꾸는 경로가 없다. |
| 중단과 조회 | 예약 직후, 합성 provider의 접수 직후, 응답 수신 후 저장 전에 자식 Node 프로세스를 종료했다. 복구는 같은 provider·모델 지문·입력·실행 ID를 사용한다. `NOT_FOUND`, `UNSUPPORTED`, `ERROR`만으로 실행 효과와 비용을 확정하지 않는다. 승인·지문 불일치면 새 조회 전송도 차단한다. |
| 취소·비용 | 시작 전 취소는 dispatch 0이었다. 시작 확인은 응답과 별도로 영속화한다. 실제 시작 확인 후 종료된 프로세스의 조회가 빗나가도 `started: true`, 비용 `null`이 남았다. 취소와 늦은 성공이 겹친 경우 확인된 합성 청구액과 receipt를 보존하고 게시를 막았다. |
| 대체 1회 | 같은 owner·작품의 승인 계보에서 확정 실패나 미시작 근거가 있고 미확정 효과가 없을 때만 명시적으로 요청한 대체 슬롯 하나를 예약한다. 서로 다른 단계가 경쟁해도 승자는 하나이고 재시작·승인 갱신 뒤에도 소비 이력이 남는다. 정산이 확인됐어도 종료가 불명이면 예약을 거부한다. 대체 provider 호출은 0회였다. |
| 후보와 게시 | 기존 `writeExclusive`로 시도·산출물 지문별 후보를 기록하고, `readBounded`와 SHA-256으로 다시 읽는다. 번역 후보는 S15-03 정규화 → S15-02 번역 검사·DAG → S15-01 판단 → S15-04 게시 영수증을 통과했다. HARD, 부분 성공, 미구현 검사, 필수 근거 누락은 게시되지 않았다. 정확한 SOFT 승인만 인정하고 경고와 사람 검토 근거 ID를 영수증에 남겼다. |
| 확정 실패 | 후보 쓰기, 관측 저장, 게시 영수증의 원자 저장을 방해하고 확정 직전 프로세스를 종료했다. 이전에 확정한 후보 바이트와 영수증, 소비 이력이 보존됐다. 미확정 쓰기는 `RESULT_UNKNOWN`이며, 복구는 저장된 후보를 재검사하거나 같은 시도를 조회한다. 게시된 후보도 바이트가 바뀌면 성공으로 반환하지 않는다. |

실행기는 테스트가 소유한 기존 디렉터리와 합성 registry, 실행 ID별 현재 승인을 읽는 동기 함수를 받는다. 취소와 게시가 경쟁하면 같은 세대의 한 쓰기만 확정되고 다른 쪽은 최신 상태에서 판단한다. 게시 직전에는 승인 스냅샷과 만료를 다시 확인한다.
