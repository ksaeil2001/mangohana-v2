# S16-06 실험 개시와 최종 인수 검증

2026-11-19 KST. **합성 검증을 마쳤고 실제 실험 개시와 최종 인수는 모두 차단됐다.** 미사용 작품과 실행 승인이 있어야 개시 근거를 기록할 수 있다. 최종 인수에는 당시 보관한 개시 기록, 네 조건의 실행·정산 영수증, 독립 평가자의 회수 기록과 사전 기준에 따른 보고서가 필요하다. 이번 요청에서 실제 평가에 제출된 근거는 없었다. ## 최초 RED와 판정 기준

최초 RED는 이전 단계의 공개 함수가 만든 합성 잠금과 짝비교 보고서를 사용했다. 미사용 이력을 빼거나 승인을 빼도 저장된 잠금은 각각 `locked`였다. 영수증 한 건을 빼거나 한 평가자의 응답만 남겨도 기존 함수는 각각 `stage16-paired-report`를 반환했다. 네 경우 모두 기대값 `blocked`와 달라 테스트 본문의 단언이 실패했다. 이 기준선이 관찰한 것은 산출물의 존재다. 실제 작업 개시나 과거의 인수 사건을 재현한 횟수는 0건이다. [최초 RED 4건](stage16-06-20261119/red-contract.log) · [기준선 연결 코드](stage16-06-20261119/red-baseline.mjs)

| 판정 지점 | 대조한 근거 | 결측·불일치 처리 |
|---|---|---|
| 개시 | Stage05 사용 권리와 동결 자료, S16-02 후보 선정·작품·문맥 노출 이력, 별도 보관한 잠금 지문, 페이지마다 네 조건에 배정한 작업과 승인 | 미사용 이력, 유효한 승인 또는 경로 준비 근거가 빠지면 개시 지문을 만들지 않는다. 열람 후 튜닝이 확인되면 기존 개발셋 강등 기록을 보존한다. |
| 당시 승인 범위 | 잠금 ID와 작업 목록 지문에 결속한 승인, 개시 때 별도로 보관한 지문 | 승인 결정이 저장 내용에 없거나 나중 승인이 기존 개시 지문과 달라지면 차단한다. 모델·단계·owner·revision은 고정한 작업 목록을 통해 대조한다. |

| 독립 평가 | 동결된 서로 다른 두 평가자·독립 그룹, 블라인드 배정과 원응답, 의미 충실도와 자연스러움 | 예정된 응답이나 한 축이 비면 차단한다. 각 축에서 두 평가자가 모두 판단한 중복 쌍이 한 건 이상 있어야 한다. 두 사람이 다른 선택을 해도 불일치로 보존하고, 명시적 판단 불가도 원장에 남긴다. 실제 범위는 신원을 확인한 측이 보관한 두 사람의 인증 근거까지 대조한다. |
| 최종 보고 | S16-05의 사전 기준과 자동 점수, 저장한 원래 보고서 및 다시 계산한 보고서 지문 | 보고서만 제출하거나 결과·비용을 사후에 바꾸면 차단한다. 악화·무차이·작은 표본에 따른 불확실성도 그대로 보고할 수 있다. |

두 공개 함수는 운영자 측의 오프라인 증거 대조용이다. 호출자가 제출한 자료와 별도로 보관한 지문이 입력된다. 실제 작품의 원본·사용권, 승인 발행자, 자원·실행 경로, 평가자 본인 확인은 해당 증거 소유자가 확인해야 한다. 제품 실행과 Permit을 제어하는 서비스 연결은 이번 범위 밖이다. [판정 함수](../../packages/evaluation/stage16-final-acceptance.mjs) · [합성 회귀](../../tests/v2/stage16-final-acceptance.test.mjs)
