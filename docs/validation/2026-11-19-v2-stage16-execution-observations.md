## 입력과 집계 기준

공개 함수 `collectStage16Observations(plan, receipts, anchors)`는 메모리에 공급한 기록을 읽는다. `plan`에는 S16-02의 잠금, S16-01 조건표와 사전 배정한 작업 목록이 들어간다. `anchors`에는 별도로 보관한 잠금 ID와 작업 목록 SHA-256을 전달한다. 영수증 발행자와 지문의 사전 보관 시점은 별도 증거가 필요하다. [구현](../../packages/evaluation/stage16-execution-observations.mjs) · [입력 예시](../../tests/v2/fixtures/stage16-observations.mjs)

- 작품·페이지마다 네 셀을 유지한다. 한 셀에 여러 작업을 배정하면 각 작업의 cold/warm 초기화 구분과 시간을 보존한다. 배정한 모든 작업이 완주해야 그 셀의 완주 수가 1이 된다.
- 전체 경로는 OCR, 번역, 복원, 식자를 요구한다. 마스크를 따로 기록하는 경로는 사전 배정에 그 단계를 포함한다. 고정 중간 입력 경로는 조건표의 중간 입력 SHA와 등록한 시작 단계부터 평가한다.
- Stage06 페이지 기록의 작업·소유 범위·원본·revision과 Stage15 원장의 실행 지문을 대조한다. 모델·처리 표식 또는 요청·관측 양쪽의 셀 이름을 함께 바꿔 붙여도 원래 실행 지문이 일치해야 한다. 같은 작업 영수증의 동일 재제출은 한 번만 센다. 같은 ID의 내용 충돌, 다른 작업에 재사용한 증거는 집계 전에 거부한다. [조건 대조 테스트](../../tests/v2/stage16-execution-observations.test.mjs) · [공급자 요청 지문 계산](../../apps/engine/stage15-provider-adapter.mjs)
- 작업별로 초기화, 단계별 상태·실패 사유, 원래 시도와 재시도·폴백·조회, 경과시간·최대 RAM과 정산을 보존한다. 조회로 나중에 결과가 확인돼도 앞선 시간 초과와 미확정 정산이 이력에 남는다. 좁은 영역만 성공하거나 최종 식자 결과 지문이 어긋나면 완주 수에서 제외한다. 시간·RAM 등 결측에는 사유를 붙인다.
- 금액은 Stage15의 USD 십진수 원장을 사용한다. 공급자 정산 근거 ID와 금액이 맞아야 확인된 0을 기록한다. 미확정 비용이나 누락된 필수 단계가 있으면 총액은 `null`이고 확인된 부분합은 남는다. 기존 배치의 번역 원장과 소수점 이하 12자리까지 대조했다. [배치 집계](../../apps/engine/stage15-batch-accounting.mjs) · [Stage06 작업 이력 집계](../../packages/evaluation/offline/operations.mjs)
